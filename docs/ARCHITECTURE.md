# アーキテクチャ

レビューするときに「どこに何があり、なぜそうなっているか」を追えるようにするための文書です。

## 全体像

```
┌──────────────────────────── フロントエンド (src/) ────────────────────────────┐
│  components/*.svelte   画面の部品。表示と入力だけ                              │
│          │                                                                    │
│  lib/store.svelte.ts   画面の状態と、利用者の操作 = アクション                 │
│          │                                                                    │
│  lib/backend.ts        Rust コマンドの呼び出し口 (コマンド名を知る唯一の場所)  │
└──────────┼────────────────────────────────────────────────────────────────────┘
           │ invoke / event
┌──────────┼──────────────── Tauri シェル (src-tauri/) ─────────────────────────┐
│  commands.rs           1 コマンド = MailService のメソッド 1 つ (丸投げ)       │
│  external_links.rs     メール内リンクを既定のブラウザへ回す                    │
└──────────┼────────────────────────────────────────────────────────────────────┘
           │
┌──────────┼──────────────── コア (crates/rumble-core/) ────────────────────────┐
│  service.rs            ユースケース層。外からはここだけを呼ぶ                  │
│     ├── imap/connection.rs   接続・再接続・タイムアウト                       │
│     ├── imap/ops.rs          IMAP 操作 (状態を持たない関数群)                 │
│     ├── imap/mapping.rs      サーバー応答 → domain 型                         │
│     ├── imap/watcher.rs      IDLE による受信トレイ監視                        │
│     ├── mime.rs              受信メールの解釈と HTML のサニタイズ             │
│     ├── smtp.rs              送信                                             │
│     ├── cache.rs             メモリ内キャッシュ (ディスクには書かない)        │
│     └── storage/             ディスクに触れる唯一の場所                       │
│  domain/               画面とやり取りするデータ型 (振る舞いなし)               │
└───────────────────────────────────────────────────────────────────────────────┘
```

依存は上から下への一方向です。`rumble-core` は Tauri を知らないので、GUI なしで
テストできます。

## 原則: メールをディスクに保存しない

rumble の存在理由です。コード上では次のように守っています。

- **ディスクへの書き込みは `storage/` に閉じ込める。** `AccountStore` (設定 JSON) と
  `SecretStore` (OS キーチェーン) の 2 つの trait がその全てで、どちらもメールを扱う
  メソッドを持ちません。
- **唯一の例外は添付ファイルの保存。** `MailService::save_attachment` が、利用者が
  ダイアログで選んだパスへ書き出します。
- **キャッシュはメモリだけ。** `cache.rs` の `MessageCache` は開いたメールの生データを
  バイト数上限つき (64 MB) の LRU で保持します。永続化の手段を持ちません。
- **フロントエンドも保存しない。** `localStorage` などは使っていません。
  `store.svelte.ts` の状態は「いまサーバーから見えているものの写し」です。

「ローカル保存を足したくなったら `storage/` に trait を増やすことになる」ので、
原則を破る変更はレビューで必ず目に入ります。

## IMAP をどう使っているか

| やりたいこと | IMAP での実現 | 場所 |
|---|---|---|
| 一覧を少しずつ表示 | シーケンス番号の末尾から範囲 `FETCH`。取るのは `FLAGS` と一部ヘッダーだけ | `ops::list_messages` |
| 検索 | `UID SEARCH TEXT` (サーバー側で全文検索) | `ops::search_messages` |
| メールを開く | `UID FETCH BODY.PEEK[]` (PEEK なので勝手に既読にならない) | `ops::fetch_raw_message` |
| 既読・スター | `UID STORE ±FLAGS.SILENT` | `ops::set_flag` |
| 移動 | `UID MOVE`。非対応サーバーでは `COPY` + `\Deleted` + `EXPUNGE` | `ops::move_messages` |
| 削除 | ゴミ箱へ移動。ゴミ箱の中では完全削除 | `ops::delete_messages` |
| 送信済みの控え | `APPEND` (Gmail は自動保存するので省略) | `ops::append_message` |
| 新着の検知 | 専用接続で `IDLE` | `imap/watcher.rs` |
| フォルダの役割 | `LIST` の SPECIAL-USE 属性。無ければ名前から推測 | `imap/mapping.rs` |

### 状態を持たない操作

`ops.rs` の関数はどれも「セッションを受け取り、対象フォルダを `SELECT` し、コマンドを
発行して返す」だけです。「いま選択中のフォルダ」のような状態を関数の外に持たないので、
1 つの関数を読めばその操作の全てが分かります。メールの特定には、接続をまたいでも
変わらない UID だけを使います。

### 接続は 1 アカウントにつき 2 本

- **操作用** (`ImapConnection`) : 一覧・取得・フラグ変更など。`tokio::sync::Mutex` で
  直列化し、1 本の接続に 1 コマンドずつ流します。
- **監視用** (`InboxWatcher`) : 受信トレイを `IDLE` し続けます。IMAP では IDLE 中に
  他のコマンドを送れないため、操作用とは分けています。

`ImapConnection::run` が接続まわりの面倒を一手に引き受けます。

1. 未接続なら接続する
2. しばらく使っていなければ `NOOP` で生存確認し、だめならつなぎ直す (スリープ復帰対策)
3. 操作にタイムアウトをかける
4. 接続が壊れた種類のエラーならセッションを捨てる (次回つなぎ直す)

そのため `service.rs` や `ops.rs` には再接続のコードがありません。

### IDLE の通知は「変わった」だけ

監視側は通知の中身を解釈せず、「受信トレイが変わった」というイベントだけを
フロントエンドへ送ります。フロントエンドは通常の一覧取得をやり直します。
差分を自前で組み立てないので、表示がサーバーとずれる余地がありません。

## フロントエンド

- **`backend.ts`** : `invoke` を呼ぶのはここだけ。Rust 側 `commands.rs` と 1 対 1。
- **`types.ts`** : `crates/rumble-core/src/domain` の型の写し (JSON は camelCase)。
- **`store.svelte.ts`** : 状態とアクションを持つ単一のストア。コンポーネントは
  ストアを読んで描画し、操作はストアのメソッドを呼ぶだけです。
- **楽観的更新** : 既読・スター・削除などは先に画面へ反映し、サーバーが拒否したら
  一覧を取り直してサーバーの状態に合わせます (正は常にサーバー)。
- **古い応答の破棄** : フォルダを素早く切り替えたとき、前のフォルダの応答で画面を
  上書きしないよう、リクエストに通し番号を振っています (`#listRequest` など)。

## HTML メールの安全対策

受信した HTML は信用できないので、三重に守っています。

1. **サニタイズ** (`mime::sanitize_html`) : スクリプト・フォーム・iframe などを除去。
2. **sandbox 付き iframe** (`HtmlBody.svelte`) : スクリプト実行を許可しない。
3. **CSP** : iframe 内から外部への通信を遮断。外部画像は利用者が「画像を読み込む」を
   押したときだけ許可します (開封確認用の画像対策)。

リンクのクリックは、iframe からウィンドウ全体への移動要求として届くので、
`external_links.rs` が横取りして既定のブラウザで開きます。外部のページが
アプリのウィンドウ内に読み込まれることはありません。

## 技術選定

| 対象 | 採用 | 理由 |
|---|---|---|
| UI | Svelte 5 + TypeScript | ランタイムが小さく、状態管理ライブラリなしで足りる |
| IMAP | `async-imap` | IDLE を含め非同期で扱える |
| メール解析 | `mail-parser` | ISO-2022-JP など日本語の古い文字コードまで面倒を見てくれる |
| 送信 | `lettre` | メール組み立てと SMTP を一手に担える |
| TLS | OS 標準 (`native-tls`) | バイナリが小さく、OS の証明書ストアをそのまま使える |
| HTML 無害化 | `ammonia` | ホワイトリスト方式 |
| パスワード | `keyring` | 各 OS の資格情報ストアを共通 API で使える |

## テスト

- **単体テスト** (`cargo test --workspace`) : ネットワークに触れない部分。
  MIME 解釈、サニタイズ、フォルダ名の変換、検索条件の組み立て、キャッシュ、
  送信メールの組み立て、設定ファイル、リンクの振り分け。
- **統合テスト** (`crates/rumble-core/tests/imap_server.rs`) : Docker の Dovecot に対して
  一覧・検索・フラグ・移動・削除・IDLE を実際に実行します。通常は `#[ignore]` です。
