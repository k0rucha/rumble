# rumble

IMAP の良さをそのまま享受する、**メールをローカルに保存しない**軽量メーラー。
[Tauri](https://tauri.app/) + Rust + Svelte 製。

## コンセプト

IMAP ではメールの正本はサーバーにあります。それなのに多くのメーラーは全メールを
手元に複製し、使うほど肥大化していきます。rumble はそれをやめました。

| | 一般的なメーラー | rumble |
|---|---|---|
| メール本体 | 全件をローカル DB に同期 | **保存しない**。開いたときにサーバーから取得 |
| 一覧 | ローカル DB から表示 | 表示するぶんだけサーバーから取得 (50 件ずつ) |
| 検索 | ローカルの索引 | サーバー側検索 (IMAP `SEARCH`) |
| 新着 | 定期的に全体を同期 | IMAP `IDLE` によるプッシュ通知 |
| 既読・スター・移動 | ローカルを変更して後で同期 | その場でサーバーへ反映 |
| ディスク使用量 | メール量に比例して増える | **増えない** |

rumble がディスクに書くのは次の 2 つだけです。

- アカウント設定 (ホスト名など) … 設定ディレクトリの `accounts.json`
- パスワード … OS のキーチェーン (Android ではアプリ専用領域のファイル)

開いたメールは体感速度のためにメモリ上へ一時的に保持しますが (上限 64 MB)、
アプリを終了すれば何も残りません。添付ファイルは、保存先を選んで「保存」したときだけ
ディスクに書き出されます。

## 機能

- 複数アカウント (IMAP + SMTP、SSL/TLS・STARTTLS)
- フォルダ一覧 (受信トレイ・送信済みなどの役割を自動判別、日本語フォルダ名に対応)
- メール一覧 (スクロールで続きを取得)、サーバー側検索
- 本文表示 (テキスト / HTML)。HTML はサニタイズし、外部画像は既定でブロック
- 既読・未読、スター、アーカイブ、フォルダ移動、削除
- 新規作成・返信・全員に返信・転送、ファイル添付
- 添付ファイルの保存
- IDLE による受信トレイのリアルタイム更新
- 送信元の検証 (DKIM / SPF / DMARC) とブランドロゴ (BIMI) の表示 → [送信元の検証](#送信元の検証)
- ヘッダー全文とメールのソース (生データ) の表示
- メールの自動分類 (個人・通知・取引・宣伝)。任意の機能で、既定では無効 → [自動分類](#自動分類)
- ライト / ダークテーマ (OS の設定に追従)
- デスクトップ (macOS / Windows / Linux) と Android。狭い画面では 1 画面 1 ペインの表示に切り替わる

キーボード: `j`/`k` または `↑`/`↓` で移動、`r` で返信 (`Shift+r` で全員に返信)、
`Delete` で削除、`⌘/Ctrl+N` で新規作成、`⌘/Ctrl+Enter` で送信。

## 使い方

必要なもの: [Rust](https://rustup.rs/)、Node.js、[pnpm](https://pnpm.io/)、
および [Tauri の前提パッケージ](https://tauri.app/start/prerequisites/)。

```sh
pnpm install
pnpm tauri dev      # 開発モードで起動
pnpm tauri build    # 配布用にビルド
```

初回起動時にアカウント追加画面が開きます。Gmail・iCloud などは通常のパスワードでは
ログインできないので、各サービスで **アプリ パスワード** を発行して入力してください。

## 送信元の検証

メールを開くと、差出人欄のドメインが本当にそのメールを出したかを確かめ、結果を色つきの帯で示します。
帯を押すと内訳 (どの署名が、どのドメインについて、合格したか) が開きます。

| 表示 | 意味 |
|---|---|
| 🟢 送信元を確認済み | 差出人ドメインの DKIM 署名を rumble 自身が検算して合格した |
| 🔵 受信サーバーが確認 | rumble では検算できなかったが、受信サーバーが DMARC 合格と記録している |
| 🟠 差出人とは別ドメインの認証のみ | 署名や SPF は通っているが、差出人欄のドメインのものではない |
| 🔴 送信元の検証に失敗 | なりすまし、または配送途中で内容が書き換えられた可能性がある |
| ⚪ 送信元を確認できません | 署名も、受信サーバーの検査記録も無い |

- **自前の検算と、サーバーの申告を分けて扱います。** DKIM 署名は DNS から公開鍵を取って rumble が
  検算します。SPF は受信サーバーにしか検査できないため、サーバーが残した記録
  (Authentication-Results ヘッダー) を読みます。こちらは送信者にも書けてしまうヘッダーなので、
  「確認済み」とは別の表示にしています。
- **ブランドロゴ (BIMI)** は、送信元を確認でき、かつドメインが DMARC で `quarantine` / `reject` を
  宣言している場合だけ表示します。**商標の証明書 (VMC) は検証していません。** ロゴは
  「そのドメインの持ち主が自分で掲げているもの」です。
- **通信について**: 検証のために、メールを開いたとき DNS (署名ドメインの公開鍵、差出人ドメインの
  DMARC / BIMI レコード) を引き、ロゴがあれば HTTPS で取得します。DNS は OS に設定されたサーバーを
  使い、Android では Cloudflare の公開 DNS (1.1.1.1) を使います (OS の設定を読むには追加の権限が要るため)。
  送信済み・下書きフォルダのメールは検証しません。
- 古いメールは、署名の期限切れや公開鍵の更新で検算できないことがあります (その場合は
  受信サーバーの記録で判定します)。

判定の規則は `crates/rumble-core/src/authenticity/verdict.rs` にあります。

帯の右の「ソース」では、ヘッダーの全文と、本文を含むメール全体を、サーバーから受け取った文字のまま
(デコードせずに) 表示・コピーできます。1 MB を超えるメールは先頭の 1 MB だけを表示します。

## 自動分類

サイドバーの「自動分類」で [TypeSafe](https://typesafe.ai) の API キーを登録すると、
一覧に出たメールを分類モデル **Jev** が「個人・通知・取引・宣伝」に分け、区分で絞り込めるようになります。

- **外部に送るもの**: 差出人・宛先・件名と、一斉配信かどうか (List-Unsubscribe などの有無) だけ。
  本文と添付は送りません。キーを登録しない限り、何も送信されません。
- **結果の保存先**: メールサーバー上のメールに IMAP キーワード (`$rumble_newsletter` など) として
  付けます。ローカルには保存しないので、ほかの端末の rumble からも同じ分類が見えます。
  Gmail などではこのキーワードがラベルとして見える場合があります。
- **費用**: 1 通につき 1 回、TypeSafe の API を呼びます (分類済みのメールは呼びません)。
- Jev は英語を中心に学習しているため、日本語の件名では精度が落ちることがあります。
- キーワードを保存できないサーバーでは、分類結果はアプリを開いている間だけ有効で、
  区分での絞り込みは使えません。

区分の定義は `crates/rumble-core/src/classifier.rs` にあります。

## Android

Android Studio (SDK・NDK) と Rust の Android ターゲットが必要です。

```sh
rustup target add aarch64-linux-android
scripts/build-android.sh    # dist-android/ に arm64 用の APK ができる
```

スクリプトは APK をビルドし、手元の端末で試せるようデバッグ鍵で署名します
(配布する場合は自分の鍵で署名し直してください)。`JAVA_HOME`・`ANDROID_HOME`・`NDK_HOME` は
未設定なら macOS の Android Studio の標準的な場所を使います。

Android 固有のコードは `src-tauri/gen/android/` にあります。ステータスバーとの重なりを
避ける処理は `MainActivity.kt`、戻るボタンの挙動は `src/lib/store.svelte.ts` の `back()` です。

デスクトップ版との違い:

- パスワードは OS のキーチェーンではなく、アプリ専用領域のファイルに保存します
  (他のアプリからは読めませんが、暗号化はしていません)
- メール作成時のファイル添付は未対応です (受信した添付の保存はできます)
- アプリを閉じている間の新着通知はありません


```sh

    -p 31993:31993 dovecot/dovecot:latest
cargo test -p rumble-core --test imap_server -- --ignored
```

コードの構成と設計判断は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) にまとめています。

## いまできないこと

- OAuth2 認証 (Outlook.com / Microsoft 365 など、パスワード認証を廃止したサービスは使えません)
- 下書きの保存 (書きかけのメールは作成画面を閉じると消えます)
- 複数メールの一括操作、スレッド表示
- HTML メールの作成、転送時の添付ファイル引き継ぎ
- 複数フォルダの横断検索
- BIMI の証明書 (VMC) の検証、ARC (転送・メーリングリスト経由の認証の引き継ぎ) の検証
- 添付だけを除いた部分取得 (メールを開くと添付ごとメモリへ取得します)
